## 建議估算（新增投入，不含已完成 CT2）

「小時」為開發者／AI 協作加人工驗收的有效投入時間，不是保證的日曆時間。以一個日文版本、繁中、現有引擎可正常跑、單人循序工作為前提。

| 里程碑 | 本階段工時 | 交付與關卡 |
| --- | ---: | --- |
| A. 限時可行性驗證 | 1–2 小時 | 驗證遊戲內主要 writer／字庫與一個實際選單或訊息；不能只再翻標題 |
| B. 最小可玩中文樣本 | 2–4 小時 | adapter、catalog／editor 參數化、主要靜態標籤原位顯示；累計 3–6 小時 |
| C. 批次翻譯与動態補全 | 2–4 小時 | 道具／HUD／選單／遊戲訊息，依 A 的實際盤點更新範圍 |
| D. 遊玩校對與回歸 | 3–6 小時 | 死亡、續關、結局等範圍路線，手機字型／排版、原版對照與正式建置 |
| **基準合計** | **8–16 小時** | 全範圍驗收的規劃預算；未知部分仍需 A 放行 |

三種情境：

- **樂觀 5–8 小時**：大部分遊戲文字共用已知 parser，文字量少，無額外圖像字／罕見分支且可快速驗收。
- **基準 8–16 小時**：需要 1–2 類額外 writer／動態參數，沿用現有顯示與編輯器。
- **保守 16–30+ 小時**：存在額外字庫／圖形文字、難到達結局、未發現資料來源或核心相容性問題。這不是上限。

**建議先授權 A 的 1–2 小時，不先承諾「比 CT2 快一半」。** A 結束以實際 writer 家族、獨立字串／字數、未知碼、可重播路線重新估算。若 2 小時仍找不到主要遊戲內來源，停止批量翻譯，交付阻塞證據與新預算。

「完整」指先約定範圍內全部文字均驗收；無法證明盤點完整、未到達結局、保留日文 fallback，就只能標示部分完成。原文是英文也需列入是否翻譯的範圍。

## token 與金錢

CT2 的 **10 小時／約 12,000 token** 是使用者回報值，且當前不是全中文化成品。不同模型、輸入／輸出、快取、子代理與訂閱計費口徑可能不同；本次沒有帳單，不把它換算成虛構的新台幣金額。

若未來使用**完全相同計數口徑**，可先拿以下作管理額度，並非由遊戲 bytes 推導的準確模型消耗：

| 範圍 | 暫訂 token 預算 |
| --- | ---: |
| A 限時勘查 | 2,000–4,000 |
| 最小可玩樣本（含 A） | 4,000–8,000 |
| 基準完成範圍（含 A–D） | 10,000–24,000 |
| 高不確定情境 | 24,000–40,000+，需重估 |

不能將這些數字視為 API 完整上下文 token 的預測；若 CT2 的 12,000 只計輸出或額度顯示，必須維持同口徑比較。

API 金額公式：`輸入 token / 1,000,000 × 輸入單價 + 輸出 token / 1,000,000 × 輸出單價`，快取與其他服務另計。訂閱方案則按實際額度／超額規則計算，不一定逐 token 收費。若人工時薪為 R，基準人力預算為 `8R–16R`；模型費、授權字型或額外裝置成本另列。現有流程不必付 OCR／外部翻譯 API 費，也不會上傳 ROM。
