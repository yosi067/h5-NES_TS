# FC 中文化最短可靠路徑

> 現況：依 CT2 實作與回歸整理（2026-09-05），適用本專案「原 ROM＋高解析度顯示翻譯」。不是通用 IPS/BPS 中文 ROM 教學。
> 核心原則：只逆向一次共用 writer，先做一個端到端樣本，不省略驗證。

## 1. 開工前：寫一頁範圍表

- [ ] ROM 雜湊、版本、mapper、PRG/CHR 大小；確認原始檔不會被改動。
- [ ] 要翻的畫面族：開場、HUD、選單、道具、對話、戰鬥訊息、死亡／續關、結局／片尾。
- [ ] 刻意不翻：密碼符號、數字、圖示、使用者指定保留的標題。
- [ ] 完成定義：每個範圍都有來源、譯文、可重播路線與畫面驗收；未到達的畫面標為未驗證。
- [ ] 能力修改與可攜存檔另列專案，不混進文字工時。

參考值：使用者回報 CT2 約 **10 小時、12,000 token**，是已投入量，**不是完整中文化成本**（動態比賽解說、部分 writer、全路線校對、能力編輯仍未完成）；token 未經帳單核對，不能當作每小時固定消耗率。

## 2. 分階段流程

| 階段 | 最小交付 | 放行／停止條件 |
| --- | --- | --- |
| 0. 限時勘查 | 雜湊、可啟動、候選 writer／指標表、範圍表 | 1–2 小時判斷是否值得做；沒有來源證據就先研究，不大量翻譯 |
| 1. 一個真實畫面 | 一段原文→來源索引→精簡中文→原位顯示 | 原 ROM 實際顯示、數字／精靈不被遮、可重播 |
| 2. 批次萃取 | 無損 IR、可編輯 catalog、候選／已驗證分開 | decode→encode 位元組一致；控制碼不得當文字 |
| 3. 依 writer 家族接入 | 各家族代表路線、來源字庫與生命週期證據 | 重用已證實的 parser，不為每句重玩找文字 |
| 4. 分批翻譯與排版 | 固定字級、術語表、整行字寬預算 | 先縮句保留意思；不縮字、不外移字幕、不任意遮黑 |
| 5. 驗收 | 自動回歸＋實際字型／手機畫面＋覆蓋矩陣 | 區分已萃取、已填稿、已接入、已走過、已校對 |

確認解析流程與來源身分後，可批量分類同族靜態記錄；執行期仍逐格驗證。「尚未跑到」不等於「找不到文字」，static candidate 也不等於已確認可翻譯文字。

## 3. 萃取與來源檢查表

- [ ] 從 PPU 寫字路徑、呼叫點、指標表回推資料，不先用 screenshot/OCR。
- [ ] 記錄實體 PRG 偏移、bank、來源 bytes、控制碼、PPU 位置與 writer；CPU 位址相同不代表同一 ROM bank。
- [ ] 原 CHR atlas 只用來核對字碼表；位元組完全相同的 CHR 副本才可加別名，不能只憑 tile 編號認字。
- [ ] 保留未知碼與未確認分類，不猜日文或能力欄位；未知不等於空白。

## 4. 顯示與排版檢查表

- [ ] 重用[顯示層](../src/game-profiles/text-overlay.ts)：原生 256×240 遮罩再放大，避免格線白縫。
- [ ] 以完成幀的 PPU fetch／寫入世代、CHR 身分、palette 判斷文字是否仍在；「執行到清字命令」不代表畫面已清字。
- [ ] 背景來源與真正勝出的精靈分開處理，畫完中文後保留游標、人物、箭頭像素。
- [ ] 固定字級，優先精簡同義句；以**完整邏輯行**計算預算，可用同列已驗證空白，不跨數值／肖像。
- [ ] `sourceBytes × 8` 只適用已證實的 8px 來源；其他遊戲先確認 8×8、8×16、合成字或自動換行，不照抄 CT2 幾何。
- [ ] 字速獨立於 CPU／音訊；中文可加快，但不提早揭露下一段腳本。
- [ ] 動態句以可驗證參數（人名、招式、數值）組成完整訊息，不分別翻片段。

## 5. 編輯與交付

重用[翻譯編輯器](../src/game-profiles/translation-editor.ts)與[交換格式](../src/game-profiles/localization.ts)：使用者只編輯 `translation`／`notes`，機器維護來源索引。換遊戲需把 CT2 專屬路徑、storage key、身分檢查與入口參數化。

- [ ] 執行期只啟用已識別 ROM，來源不符安全回退。
- [ ] 正式版不顯示開發控制、不套本機草稿；開發模式明確條件開啟。
- [ ] 不自動覆寫使用者自訂譯文（未來可做舊預設／新預設／使用者修改三方合併，衝突需呈現）。
- [ ] 交換檔簡單、證據檔可詳細；翻譯者不編輯 PRG offset 或控制碼。

## 6. 常見耗時陷阱

| 陷阱 | 替代方式 |
| --- | --- |
| 重複截圖找字、每句從頭玩 | 指標表＋writer 批次萃取；固定輸入重播、路線 checkpoint |
| 先翻完才發現字框放不下，或為過測試而縮字／搬到畫面外 | 先定字級與整行預算；超限回報，不把 fallback 當成功 |
| 只看當前 nametable | 使用完成幀證據，避開 VBlank／DMA 的時間差 |
| 反覆按 A 以為能走遍分支 | 確認原遊戲輸入；CT2 指令要先方向鍵且會閃爍，稀疏抽樣會漏看 |
| 用不完整存檔當可靠 checkpoint | 先證明硬體狀態完整；否則用 deterministic input replay |
| 相信子代理摘要或既有註解的「已驗證」 | 對照原碼、原始 artifacts、測試；錯誤地址與舊架構很容易混入 |
| 把 catalog 填滿稱作全中文化 | 維護分層覆蓋矩陣，沒有全遊戲分母就不報完成百分比 |

## 7. 最低驗收清單

- [ ] 原 ROM 雜湊與輸入 bytes 未變；無文字控制／遊戲資料被意外改寫。
- [ ] 萃取 round-trip、catalog 身分／重複／缺漏／未知字碼檢查。
- [ ] 開始、暫停、清字、換行、換頁、換 CHR、sprite 遮擋、palette 變化、重設、讀檔。
- [ ] 靜態標籤、動態名字與數字分開；密碼可照原順序輸入。
- [ ] 固定字級與實際 Canvas 字寬；桌面、手機橫直向、fractional scale 無白縫與裁切。
- [ ] 原版／觀察器版本同輸入對照 CPU／mapper／畫面；音訊及 DMA 變更另有回歸。
- [ ] 全部宣告範圍有可重播路線，未覆蓋與刻意保留內容有清單。
- [ ] 正式建置與開發模式分別檢查；Git 不新增 ROM、帳密、快取與無用截圖。

## 8. 控制時間與 token

- 每階段保存小型證據表（結論、來源、未解項目、下一個實驗），不重貼整個 catalog；搜尋先限範圍，測試摘要保留失敗重現。
- 代理可平行做獨立研究／校對，但不同時改同一檔案；翻譯按術語與畫面族批次處理。
- 每 1–2 小時檢查是否產出新的**可驗證覆蓋**；沒有就縮小實驗或重估。工時包含人工遊玩與校對，token 低不保證效率高。
